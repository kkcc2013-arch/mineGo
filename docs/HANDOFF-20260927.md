## 6. 已发现、尚未修复的缺陷（建议优先）

- `backend/migrations/*.sql` 从不执行（威胁检测等表不存在）。
- `.github/workflows/security-compliance-scan.yml` 在 kube-bench 安装失败后写入**伪造的扫描结果**。

其他：
- `frontend/game-client/tests/unit/catch-effects.test.js`（REQ-00081）是 Jest 写法且 import 路径错误，一直无法运行。
- lockfile 中 `undici@8.5.0` 要求 Node ≥ 22.19，而 `docker-compose.yml` 的服务镜像是 `node:20-alpine`、宿主机是 22.13。

## 10. 协调者的合并流程（供参考）

1. 集成分支工作区干净时执行 `git merge --no-ff --no-commit work/<分支>`。若分支历史里含 `.github/workflows` 改动，改用 `--squash`。
2. 解决冲突。常见冲突：
   - `backend/package.json` 的 `test:unit`：两边用例并集。
   - 网关 `WS_TARGETS`：加一行。
   - `index.html` 的 `initFeatures` 参数：取并集。
   - 服务入口文件：保持第一行 `initTracing`。
3. 用脚本解决冲突时，正则必须按行首锚定 `^=======$`。注释里的 `// =====` 会被误匹配，曾因此破坏过一次文件。
4. 静态检查：
   - 所有改动的 JS 过一遍 `node --check`（前端 ESM 用 `node --input-type=module --check < 文件`）。
   - `index.html` 内联脚本单独抽出来检查。
   - `cd backend && node ../scripts/check-deps.js`。
   - `node scripts/api-lint.js`，以及 `--check-docs`。
   - `node scripts/contract-snapshot.js --check`。
   - 宿主机能跑的 `node --test`。
5. 提交 `merge(Exx): …`，正文写明冲突处理与检查结果，注明"未运行服务验证"。
6. 更新 `tools/epic_status.json`，运行 `python3 tools/render_plan.py`，提交进度并推送。
